# Design docs

Personal study notes, written for learning rather than as project
documentation. Tracked in the repo for now; the ignore rule for this folder is
commented out in `.gitignore` if you want it private again.

After every completed feature, `/complete` writes a first-principles
explanation here: what the feature is, why it exists, the concepts it
introduces, how it's architected, and what was actually built, aimed at
someone learning AI engineering (agents, tool calling, Pydantic AI, evals,
metrics, observability) for the first time.

Files are named to match their archive in `blueprint/history/features/`,
for example `02-backend-reorganization.md`.
